# Go Coding Standards

**Important** never manually edit `go.mod` files in a go project. Just run `tidy` and it will auto get|download

---

## Language & Version

- Use **Go 1.27+**
- No unused imports or variables
- Keep functions under 50 lines when possible
- No global state — inject all dependencies via constructors

---

## Architecture

Follow a strict **layered architecture** — Handler → Service → Repository.

- **Handler** — parses request, validates input, calls service, writes response
- **Service** — owns all business logic
- **Repository** — database access only, no business logic

Each layer depends on the layer below via **interfaces**, never concrete types.

```go
// always depend on interfaces
type ProductService interface {
    Create(ctx context.Context, input CreateProductInput) (*domain.Product, error)
    List(ctx context.Context, filter ProductFilter) ([]*domain.Product, error)
}
```

---

## HTTP

- Use Go standard library `net/http` only — no third-party routers (no Gin, Echo, Chi)
- Go 1.22+ native routing supports method + path matching out of the box

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /api/v1/products", h.List)
mux.HandleFunc("POST /api/v1/products", h.Create)
mux.HandleFunc("PATCH /api/v1/products/{id}", h.Update)
mux.HandleFunc("DELETE /api/v1/products/{id}", h.Delete)
```

- Always version routes under `/api/v1/`
- Use middleware chaining for auth, logging, and permission checks
- Never write raw response logic in handlers — always use `libs/go/response` helpers

## File Organization

```
internal/
  handler/
    product/
      handler.go
      handler_test.go
  service/
    product/
      service.go
      service_test.go
  repository/
    product/
      repository.go
      repository_test.go
  middleware/
    auth.go
    permission.go
config/
  config.go
cmd/
  server/
    main.go       # API server entrypoint
```

Group by **feature** within each layer. No `main.go` at the project root — entry points live under `cmd/`.

## Naming

- Files: `snake_case.go`
- Packages: short, lowercase, no underscores (`handler`, `service`, `repo`)
- Types and interfaces: `PascalCase`
- Functions and methods: `camelCase`
- Constants: `SCREAMING_SNAKE_CASE`
- Interface names describe behavior, not type — `ProductRepository`, not `IProduct` or `ProductRepo`

## Configuration

- All configuration is loaded from ENV variables — no hardcoded values
- Use `github.com/rodentskiedev/go-libraries/lib/env` to read ENV — never use `os.Getenv` directly
- The second argument to `env.GetEnv` is the fallback value

```go
import "github.com/rodentskiedev/go-libraries/lib/env"

host := env.GetEnv("HOST", "localhost")
port := env.GetEnv("PORT", "8080")
```

- Define a `Config` struct per app and populate via `env.GetEnv` on startup

```go
type Config struct {
    DatabaseURL           string
    RabbitMQURL           string
    GSMPorts              []string
    WorkerPollInterval    time.Duration
    WorkerRetryWindowDays int
}

func LoadConfig() Config {
    return Config{
        DatabaseURL:           env.GetEnv("DATABASE_URL", ""),
        RabbitMQURL:           env.GetEnv("RABBITMQ_URL", ""),
        WorkerPollInterval:    env.GetEnv("WORKER_POLL_INTERVAL", "30s"),
        WorkerRetryWindowDays: env.GetEnv("WORKER_RETRY_WINDOW_DAYS", "5"),
    }
}
```

## Database

- Use **GORM** for all database access
- Use `UUID` primary keys — generated by PostgreSQL (`gen_random_uuid()`), not the backend
- All write operations must use GORM transactions if multiple tables are affected

```go
err := db.Transaction(func(tx *gorm.DB) error {
    if err := tx.Create(&product).Error; err != nil {
        return err
    }
    if err := tx.Create(&variant).Error; err != nil {
        return err
    }
    return nil
})
```

- Use **cursor-based pagination** only — never offset pagination

---

## Redis

- Use Redis for **permission caching only** — `permissions:{role_id}` keys with TTL
- Redis access lives in a dedicated `cache` package, not in repositories or services directly
- Always set TTL explicitly — never cache without expiry

```go
err := cache.Set(ctx, fmt.Sprintf("permissions:%s", roleID), payload, 15*time.Minute)
```

- On cache miss, re-fetch from the database and re-cache — the middleware handles this transparently
- Never store sensitive data (passwords, tokens) in Redis

## Logging

Use `github.com/rodentskiedev/go-libraries/lib/logger` for all logging. Never use the standard `log` package.

```go
import (
    "github.com/rodentskiedev/go-libraries/lib/logger"
    "go.uber.org/zap"
)

log := logger.New()
defer log.Sync() //nolint:errcheck

log.Info("something happened", zap.String("key", "value"))
log.Fatal("fatal error", zap.Error(err))
```

- `logger.New()` returns a `*zap.Logger` — production logger in all envs, no-op when `ENV=test`
- Always `defer log.Sync()` after creating the logger
- Pass structured fields (`zap.Error`, `zap.String`, etc.) — never use format strings

---

## Error Handling

- Always handle errors explicitly — never ignore them
- Wrap errors with context using `fmt.Errorf`
- Log the error with the file and line context for easy debugging

```go
if err := s.repo.Create(ctx, tx, &product); err != nil {
    log.Error("create product failed", zap.Error(err))
    return fmt.Errorf("create product: %w", err)
}
```

- Define error types in `apps/api/pkg/apperror`

```go
var (
    ErrNotFound     = errors.New("not found")
    ErrUnauthorized = errors.New("unauthorized")
    ErrForbidden    = errors.New("forbidden")
    ErrConflict     = errors.New("conflict")
)
```

- Map errors to HTTP status codes in the **handler only** — never in service or repository

---

## Context

- Always pass `context.Context` as the **first argument** to service and repository functions
- Use context for request-scoped values (`account_id`, `role_id`) and cancellations
- Never store context in a struct

---

## Dependency Injection

- Use constructor functions — never global variables

```go
func NewProductService(repo ProductRepository, db *gorm.DB) ProductService {
    return &productService{repo: repo, db: db}
}
```

## Security

- Hash passwords with **bcrypt** — never store plaintext
- Use **JWT** for authentication with short expiry
- Validate and sanitize all inputs before passing to the service layer
- RBAC permission checks are enforced in middleware — never in service or handler directly

---

## Testing

- Mock all interfaces — no real database in unit tests
- Integration tests live in `test/` and may use a real PostgreSQL instance
- Test files live next to source: `service_test.go` beside `service.go`
- Add cover option in `projects.json` if not yet added 

```json
"targets": {
    "test": {
        "options": {
            "cover": true
        }
    }
}
```

- Coverage should be atleast 90%, if possible always 100%

### When to write a test

Use judgment — not every function needs a test. Write a test when:

- The function contains **business logic** (conditions, calculations, state transitions)
- The function can **fail in non-obvious ways** (e.g. edge cases, error paths)
- The function is a **service method** — these almost always warrant tests
- The function involves **input validation or transformation**

Skip the test when:

- The function is a **simple passthrough** (e.g. a repository method that just calls GORM with no logic)
- The function is **trivially correct** and has no meaningful branches
- The function is a **constructor** that only assigns fields

When in doubt: if breaking the function would be hard to catch without a test, write one.

## Code Quality

- No commented-out code unless explicitly noted
- No unused imports or variables
- Export only what is necessary — keep internals private
- No `any` types — use proper types or `interface{}` with a clear comment explaining why
- Prefer early returns over nested conditionals

```go
// good
if err != nil {
    return fmt.Errorf("create product: %w", err)
}
// continue happy path...

// avoid
if err == nil {
    // happy path deeply nested...
}
```

## Database Tooling

### ORM — GORM
- `api` uses GORM for **reads and writes** (`Create`/`Save`/`Update`/`Delete`)
- No shared `libs/db` — each app's repository package defines its own private `record` struct scoped to the table(s) it owns, mapped via `TableName()`
- Define models manually with only the fields the repository needs

**Soft delete**

- Tables with a `deleted_at` column are soft-deleted: `users`, `roles`, `policies`, `medicines`, `suppliers`, `purchase_orders`. Their `record` declares `DeletedAt gorm.DeletedAt`, so GORM filters out deleted rows on every query and turns `Delete` into an `UPDATE`
- Tables without a `deleted_at` column must **not** declare `DeletedAt`
- Do not embed `gorm.Model` — its `ID` is a `uint` and this project uses UUID primary keys. Declare `ID`, `CreatedAt`, `UpdatedAt` and `DeletedAt` on the `record` instead, which is the same set of fields
- Use `Unscoped()` when a query must see soft-deleted rows, e.g. a uniqueness check against a table-wide `UNIQUE` constraint

**Base model convention (soft delete):**
```go
type record struct {
    ID             uuid.UUID      `gorm:"type:uuid;primaryKey;default:gen_random_uuid()"`
    Name           string         `gorm:"type:text;not null"`
    Barcode        string         `gorm:"type:text;not null"`
    BatchNumber    *string        `gorm:"type:text"`
    ExpirationDate time.Time      `gorm:"type:date;not null"`
    Quantity       int            `gorm:"type:int;not null"`
    CreatedAt      time.Time
    UpdatedAt      time.Time
    DeletedAt      gorm.DeletedAt `gorm:"index"`
}

func (record) TableName() string {
    return "medicines"
}
```

> The repository's internal `record` type is never exposed outside the package — map to/from `domain.Medicine` at the repository boundary.

### Migrations — Goose
- Used to manage schema versioning
- Migration files live in `apps/migration/transactions/`
- Use SQL migration format (`.sql` files)
- Run manually via the `migration` app CLI — never auto-run on startup

**Migration file naming convention:**
```
apps/migration/transactions/
├── 00001_enable_extensions.sql
├── 00002_create_users_table.sql
└── ...
```

**Goose directions in each file:**
```sql
-- +goose Up
CREATE TABLE medicines (...);

-- +goose Down
DROP TABLE medicines;
```
