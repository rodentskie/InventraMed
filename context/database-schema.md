## Database Schema

PostgreSQL, managed via GORM (models) + Goose (migrations). UUID primary keys generated by PostgreSQL (`gen_random_uuid()`).

Kept intentionally simple for the current stage — two concerns: **access control (RBAC)** and **medicine inventory**.

---

## Access Control (RBAC)

Modeled after AWS IAM: **users** are assigned **roles**, **roles** are attached to **policies**, and a **policy** is a simple `{effect, action, resource}` statement. Nothing about "what a role can do" is hardcoded — it's all data, so new roles/permissions are a row insert, not a deploy.

### `users`

| Column          | Type      | Notes                     |
|-----------------|-----------|----------------------------|
| id              | uuid (pk) | `gen_random_uuid()`         |
| email           | text      | unique                      |
| password_hash   | text      |                              |
| name            | text      |                              |
| created_at      | timestamptz |                            |
| updated_at      | timestamptz |                            |

### `roles`

| Column       | Type      | Notes                                   |
|--------------|-----------|-------------------------------------------|
| id           | uuid (pk) |                                            |
| name         | text      | unique, e.g. `admin`, `staff`, `collaborator` |
| description  | text      | nullable                                  |
| created_at   | timestamptz |                                          |
| updated_at   | timestamptz |                                          |

### `policies`

| Column       | Type      | Notes                                                        |
|--------------|-----------|-----------------------------------------------------------------|
| id           | uuid (pk) |                                                                   |
| name         | text      | unique, e.g. `medicine-full-access`                              |
| effect       | text      | `allow` \| `deny`                                                |
| action       | text      | e.g. `medicine:create`, `medicine:read`, `medicine:*`            |
| resource     | text      | e.g. `medicine:*` (no per-record resource scoping yet — start with `*`) |
| created_at   | timestamptz |                                                                 |
| updated_at   | timestamptz |                                                                 |

### `user_roles` (join)

| Column    | Type      |
|-----------|-----------|
| user_id   | uuid (fk → users.id) |
| role_id   | uuid (fk → roles.id) |

Primary key: `(user_id, role_id)`

### `role_policies` (join)

| Column      | Type      |
|-------------|-----------|
| role_id     | uuid (fk → roles.id) |
| policy_id   | uuid (fk → policies.id) |

Primary key: `(role_id, policy_id)`

### Evaluation rules (IAM-style)

1. Default is **deny**.
2. Collect every policy attached (via role) to the requesting user.
3. If **any** policy explicitly denies the requested `action`/`resource` → **deny** (deny always wins).
4. Else if **any** policy allows it → **allow**.
5. Else → **deny**.

`action` and `resource` support a trailing `*` wildcard (e.g. `medicine:*` matches `medicine:create`, `medicine:read`, ...).

## Medicine Inventory

### `medicines`

| Column           | Type       | Notes                                          |
|-------------------|------------|--------------------------------------------------|
| id                | uuid (pk)  |                                                    |
| name              | text       |                                                    |
| barcode           | text       | unique — generated per medicine, not scanned from a physical code |
| batch_number      | text       | nullable                                          |
| expiration_date   | date       |                                                    |
| quantity          | int        |                                                    |
| created_by        | uuid (fk → users.id) | nullable                                 |
| created_at        | timestamptz |                                                   |
| updated_at        | timestamptz |                                                   |

Expiration status (green / yellow / red) is **not stored** — it's derived at read time from `expiration_date` vs. today, using `settings.warning_threshold_days` below. This keeps status always correct without a background job to keep a column in sync.

### `settings`

Single-row config table.

| Column                   | Type | Notes                                               |
|---------------------------|------|--------------------------------------------------------|
| id                        | uuid (pk) |                                                     |
| warning_threshold_days    | int  | default `30` — days before `expiration_date` to switch green → yellow |

Status derivation:

- `expiration_date < today` → **red** (expired)
- `expiration_date - today <= warning_threshold_days` → **yellow**
- otherwise → **green**
